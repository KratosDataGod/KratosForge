## Outcome

**Changes Required** (docs only). Once the pipeline-schedule gap is documented (finding 1), this review recommends **Accepted with Documented Limitations**.

Criterion 1 is met. Check now now collects saved queries and the `.sql` files of warehouse projects, and a policy that names SQ rules gets pass or findings from them. Criterion 2 is met for notebooks that a schedule on this PC runs directly. Two kinds of scheduled notebook still don't get NB004 or NB008. The first is a notebook that only a Fabric schedule runs, and users are told about it. The second is a notebook that only a pipeline schedule on this PC (#791) runs. The PR names this one as a known limitation, but the docs and the inventory don't mention it.

Recommended by: Engineering quality review. Decided by (product owner): pending.

## Findings

| # | Severity | Finding | Where | Status |
| ---: | --- | --- | --- | --- |
| 1 | should fix | A notebook that only a pipeline scheduled on this PC (#791) runs isn't marked scheduled, so NB004 and NB008 never check it. The PR names this as a known limitation, but `docs/governance.md:217` only mentions Fabric schedules, and so does the FEAT-GOV-09 limitation. Users with a pipeline-run notebook would read a "not checked" result as covering their case. Either say so in both places and track it in a backlog item, or count the notebooks that a scheduled pipeline's notebook activities run. | `local_schedules.py:232-240`; `docs/governance.md:217`; `FEATURE_INVENTORY.md` FEAT-GOV-09 | Open |
| 2 | should fix | The backlog and inventory don't record the work. PB-111 is still `Proposed` with no `prs`, and FEAT-GOV-09's PR list lacks #798. | `docs/product/PRODUCT_BACKLOG.json` PB-111; `FEATURE_INVENTORY.json` FEAT-GOV-09 | Open (with the outcome) |
| 3 | note | Every SQL item is checked as `target: "warehouse"`, including saved queries written for an endpoint or a SQL database. Rules whose result depends on the target can then be wrong for those scripts. This is documented. | `checks_service.py:243,265` | Documented |
| 4 | note | SQL items and notebook items cover the whole PC (every saved query and every opened repository's warehouse projects), not only the open project's, though the page is "Check this project". This was already true for notebooks (#664 nit). | `checks_service.py:207-266` | Note |
