## Acceptance criteria

| # | Criterion (copied from the backlog item) | Result | Evidence |
| ---: | --- | --- | --- |
| 1 | Uninstall removes every grant the AppContainer added, or a confirmed Diagnostics action does | Met, by the confirmed action | Settings > Advanced > Exercise sandbox > **Remove exercise permissions** asks first (confirmDialog) and calls `academy_sandbox_remove_grants`, which runs `revoke_runtime()` on the recorded paths and the engine's own (#1820). Security (2026-11-04) chose no uninstall step: on the app-owned engine folder the grant names only KratosForge's own capability, so it is inert after uninstall. enterprise-install.md and grading-sandbox.md say to run the action before uninstalling (#1821) |
| 2 | Removal is idempotent and leaves no grant behind on a runtime that is still in use elsewhere | Met | Removing the capability's entry from a path is harmless if it is missing, and paths Windows won't change are listed with a Try again. The next exercise run adds the grant back, which the confirm says. Nothing is removed while an exercise runs (#1823, `test_nothing_is_removed_while_an_exercise_runs`) |
| 3 | A test shows grants before and none after | Met | `test_sandbox_status_counts_the_runtime_grants_on_record` and `test_removing_the_sandbox_grants_answers_removed_and_failed` check the record, the status count and the answer's shape with `revoke_runtime` stubbed. On Windows CI, `test_settings_shows_the_grants_and_removes_them` (#1823) runs an exercise in the AppContainer, sees granted > 0, removes them all with none failed, then sees granted == 0 and no ACE left on the interpreter |
