# Mutation testing, batch 530

A re-score of `git/ops.py` on today's `main`, with `--kinds all`. It runs Git's clone, fetch, pull and push in the background, with progress, cancel and how a run ends. It was last scored in batch 272 at **93.3%** (kinds all). Since then, #3240 made the run's time limit an awake-time timer (`AwakeTimer`), so a PC that slept doesn't stop a clone for time it didn't run. That is not an open bug fix, and it took the old timer's mutants away, so the module now has 147 mutants, not 153.

The run was at `main` be5ef815c (2026-11-28), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6, with each test set run with `-x`. The per-mutant timeout was raised from 120 to 600 seconds by a wrapper that sets `mutate.TIMEOUT`, with the tool unchanged; no mutant's run timed out. Each pytest session got a fresh temporary folder. The module has 147 mutants, so all of them ran. The test set was batch 272's (test_git, test_git_ops_edges and test_git_ops_mutation) and test_subprocess_timeouts, which #3240 added and which checks this module's timer. They first passed once on the unmutated copy, and none of them reads `docs/`, `examples/` or `app/`, so nothing was left out. As in test_git_ops_edges.py, a small Python program stands in for git, so no network is needed.

Before the "after" run, the new test passed in a copy of `sidecar/` on its own and against the module as `ast.unparse` writes it. It also passes on DuckDB 2.
