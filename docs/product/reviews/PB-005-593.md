## Outcome

**Changes Required** (recommended).

The encryption part looks right in code, and its tests fail on the code from before #593. Criterion 2 isn't fully met. The app and `run-schedule` each keep the whole cache in memory and write it back with no lock and no re-read, so the last writer wins. A scheduled run that is still going when the person clicks Sign out writes the signed-out account back (shown below). That behaviour predates #593, but this item's criterion asks for it to be safe. The DPAPI calls themselves can't run here: whether another Windows user can't read the cache is checked only by reading the code, plus a Windows CI test whose run wasn't seen.

Recommended by: Engineering quality review. Decided by (product owner): Chris, "I approve all of these move these forward" on 2026-10-28 (project message cmsg_018T4o2pQdpbLBNhHpgVNNGpFeQHvbSrE9FwPZyTzr8ao4), on the acceptance batch: Kept In review: finding 1 is still open.

## Findings

| # | Severity (blocking / should fix / note) | Finding | Where | Status |
| ---: | --- | --- | --- | --- |
| 1 | blocking (for criterion 2) | The app and `run-schedule` each write their whole in-memory cache with no lock and no merge. A Sign out, or the sign-out after a disallowed tenant (`_check_tenant`, auth.py:263-272), is undone when a run that was already going saves. The other way round, a new sign-in in the app (for example another account) is overwritten by an older copy, and the next scheduled run uses the old account. Fix: take a lock file around read, merge and write, and re-read the file before each save (as msal-extensions' `PersistedTokenCache` does). At least, have a save after sign-out win, or have runs reload before saving. Present before #593. | sidecar/fabric_desktop/auth.py:213-230, 298-301 | Open |
| 2 | should fix | On Windows, `os.replace` fails with PermissionError if the other process has `msal_cache.bin` open at that moment (Python opens files without `FILE_SHARE_DELETE`). `_save` doesn't catch it, so the token call that saved fails (auth.py:257, 278). The window is short (`read_bytes` at start-up). A lock (finding 1) or a retry would close it. Code reading only. | auth.py:230 | Open |
| 3 | should fix | Nobody has checked on Windows that a second Windows account (or the same profile read from another PC) can't use the file, or that a schedule run by Task Scheduler decrypts it. That needs Chris's check (FEAT-AUTH-03 next action) plus a second local account. | Windows PC | Open: Chris |
| 4 | note | Migration replaces the plain file in place but doesn't wipe it. Old plain contents can stay in free disk space, shadow copies or a backup taken before the upgrade, and a stray plain `msal_cache.bin.*.tmp` from an older build is never removed. Refresh tokens from before the upgrade stay valid until they expire or are revoked; signing out and in again replaces them. | auth.py:189-193 | Open: say it in security.md or delete `*.tmp` on start |
| 5 | note | FEAT-AUTH-03's known limitation says DPAPI is checked only with the Windows call faked. `test_real_dpapi_round_trip` runs the real call on the Windows CI runner. | FEATURE_INVENTORY.md:524 | Open: product data owner |
