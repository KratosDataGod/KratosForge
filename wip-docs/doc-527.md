# Mutation testing, batch 527

A re-score of `audit_anchor.py` on today's `main`, with `--kinds all`. It records the end of an audit trail in the Windows Application event log and reads it back, so a trail rewritten in its own folder can be told apart. It was last scored in batch 269 at **87.1%** (kinds all). Since then, #3158 let a moved trail be checked against the records for the folder it was written in and added a short cache of reads, #3225 added `kind()`, which says why a record couldn't be written (access denied, a full log, or the service unavailable), and #3232 touched the module's reader limits. None of these is an open bug fix.

The run was at `main` be5ef815c (2026-11-28), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6. The per-mutant timeout was raised from 120 to 600 seconds by a wrapper that sets `mutate.TIMEOUT`, with the tool unchanged; no mutant's run timed out. Each pytest session got a fresh temporary folder. The module now has 167 mutants, so a sample of 150 was run. The test set was batch 269's (test_audit_anchor and test_audit_anchor_mutation) and the two files added on `main` since (test_audit_anchor_failures and test_audit_anchor_windows_paths). They first passed once on the unmutated copy, and none of them reads `docs/`, `examples/` or `app/`, so nothing was left out.

Before the "after" run, the new tests passed in a copy of `sidecar/` on its own and against the module as `ast.unparse` writes it. They also pass on DuckDB 2.
