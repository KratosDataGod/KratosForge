# Authorization matrix

Each way into KratosForge that changes something, and the check that decides whether it may: the
engine methods the app window calls, the local API and MCP capabilities external tools call, the
VS Code editor channel, and `kratosforge://` links. Sections 1 to 3 are generated by
`.github/scripts/authz_matrix.py` from the code. Re-run it after adding a method or capability:

```
cd sidecar
python ../.github/scripts/authz_matrix.py > ../docs/audits/AUTHORIZATION_MATRIX.md
```

The tables are found by reading the code, not by running it. Treat each row as a pointer to where to
look, and read the method before relying on it.

## Where a check is made

| Way in | Who can reach it | Where the check is |
|---|---|---|
| Engine methods (section 3) | Only the app window. The engine reads requests on the pipe the shell started it with, and nothing else can reach it. | In the method, for this PC's own files and settings. In the platform, for shared records (section 1). In Fabric, for workspaces, items and OneLake: every Fabric call runs as the signed-in person, so Fabric's workspace roles and item permissions apply. |
| Platform operations (section 1) | This app, and anyone who can run UDF_Platform in the Platform workspace. | Inside each operation, by the caller's sign-in name (`by`), never by an argument. |
| Local API and MCP (section 2) | Connected tools on 127.0.0.1, as this Windows account (`integrations/peer.py`). | `PermissionAuthorizer.check`, once, for every transport. |
| VS Code editor channel (`editor_channel.py`) | A paired VS Code window on 127.0.0.1, as this Windows account, with no browser Origin. | Pairing needs the hello from this user's data folder, and the person approves it in the app. Calls need the pairing's token. Runs and stops go into the audit trail, and nothing here changes settings or pairings beyond ending the caller's own. |
| `kratosforge://` links (`app/src-tauri/src/deep_link.rs`) | Any program, browser or terminal on the PC. | A link only shows a notebook or a page; nothing it says is run. Network paths are refused before they are read. |
| Organization policy (`app_settings.py`) | IT, through the policy file. | `app_settings.save` refuses a setting the policy fixes. The platform's own settings check `_platform_source() == "policy"`. |

## How to read section 3

- **this PC**: the method changes files, settings or local tables under this Windows user's data folder or a folder the person picked. The check is the person's own Windows account.
- **Fabric or OneLake**: the change is made with the signed-in person's token, so Fabric decides. A method listed with `confirm or approve argument` does nothing until the app sends the person's confirmation, and `risk check` ones run the capacity risk check again in the engine.
- **platform: …**: the operations named, each checked as section 1 says.

## Review notes

Checked by hand on 2026-11-06, alongside the tables:

- Every platform operation that changes something makes its own check, except those listed in section 1 with a reason. The test `test_authz_matrix.py` fails when a new operation is added without one.
- Approving a shortcut request makes the shortcut as the approver, under the shortcut rules, after the platform checks that the approver may decide. The copies in other environments follow the approver's own rights there.
- Undo on Shortcuts > Changes now runs the shortcut rules a new shortcut does.
- Claiming, adding and removing a platform admin now names any environment's platform that didn't take the change, and a second removal finishes it.
- The local API offers only the permissions in `permissions.OFFERED`. Every capability that changes something outside the calling tool's own executions asks the person each time.
