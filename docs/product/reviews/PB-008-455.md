## Outcome

**Accepted with Documented Limitations** (recommended).

The view keeps top-level pages and pop-ups on eight exact hosts and sends every other web link to the default browser. The host match is exact and holds up against look-alike hosts, userinfo, ports, case, trailing dots and percent-encoding. The Rust tests that cover this are in `main.rs`, and the CI `shell` job runs `cargo test` on every pull request and on main. The shell can't be built here, so I didn't run the tests in place. I copied the filter and its tests verbatim into a small crate and ran them there instead. Limits: images, scripts and frames inside a page aren't filtered, and I couldn't check the behavior on Windows or see a CI run result. FEAT-FAB-05 in the inventory still describes the old filter.

**Allowed hosts** (exact match, lower-cased by the `url` crate): `app.fabric.microsoft.com`, `app.powerbi.com`, `login.microsoftonline.com`, `login.microsoft.com`, `login.windows.net`, plus `device.login.microsoftonline.com`, `autologon.microsoftazuread-sso.com` and `login.live.com` (added by #455). An organization can add exact DNS names with `fabric_view_sign_in_hosts` in `%ProgramData%\FabricDesktop\policy.json` (`policy_sign_in_hosts` and `dns_name`, main.rs:129–147). Wildcards, ports, schemes, userinfo, trailing dots and IP addresses are dropped there. The view also starts on `about:blank`, which isn't allowed as a pop-up.

**Matching:** the code compares `url.host_str()` for exact equality, not by suffix. In the harness, these went to `Browser`: `evil-fabric.microsoft.com.attacker.com`, `app.fabric.microsoft.com.attacker.com`, `app.fabric.microsoft.com@evil.com`, `login.microsoftonline.com%2F@evil.com`, `app.fabric.microsoft.com%2eevil.com` (decodes to `.evil.com`), `app.fabric.microsoft.com.` (trailing dot), `:8443` and `:444` ports, Cyrillic `а`, `127.0.0.1` and `[::1]`. Uppercase hosts and an explicit `:443` stay, because the `url` crate normalizes both. The `url` crate parses `app.fabric.microsoft.com\@evil.com` with host `app.fabric.microsoft.com` and path `/@evil.com/`, the same way WHATWG browsers do, so it stays on Fabric.
