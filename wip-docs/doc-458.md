One module not scored before, run with `--kinds all`:
- L3 behavioral semantic parity, SQL side: each SQL side's measure built into a DuckDB query within depth, measure and aggregate caps, run on fixed controlled datasets in a fresh in-memory database, and two SQL sides' values compared within tolerances, with a DAX side recorded as not run (`semantic_parity_l3.py`).

The run was at `main` a73ebb71 (2026-11-24), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6. Each pytest session got a fresh temporary folder, so a mutant can't leave one that breaks later runs. Each test set was run with `-x`. The module has 267 mutants, so a sample of 150 was run. `main` hasn't changed this module since.

The test set was test_semantic_parity_l3 and test_semantic_parity_l3_cov32.

Before the "after" run, the new tests passed in a copy of `sidecar/` on its own and against the module as `ast.unparse` writes it. They also pass on DuckDB 2.0.0. The "after" run reran the 14 survivors with the new tests added.

### What the survivors were, and the tests that now kill them

- **semantic_parity_l3.py**:
  - A measure reference 8 levels deep is past the depth cap, and 7 levels isn't.
  - 64 aggregates in one measure are allowed and the 65th isn't. A side may reach 2,000 aggregates in all and not one more.
  - 200 measures run on one side, and the 201st is noted as not run.
  - A referenced measure's aggregates are counted once, not with one extra.
  - SUM over a text column names the value class ("text") in its reason.
  - A measure that reads a refused measure, directly or through another, takes that measure's own error, not one of its own.
  - Only measure rows on both sides get a behavior; a measure on one side only and every other row don't.
  - A side that can't be read a second time is an error that names it.
  - A DAX side marked as run, even without results, is refused.
  - Equal values are the same. A gap exactly at the tolerance is within it.
  - → `test_semantic_parity_l3_mutation_b.py`.
