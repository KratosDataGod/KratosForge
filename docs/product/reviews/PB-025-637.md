## Outcome

**Accepted with Documented Limitations** (recommended).

The explorer lists schemas, tables, views, stored procedures and functions with columns, and Script as gives SELECT TOP 100, CREATE, ALTER and DROP without running anything. Both PRs' browser tests fail on the code before them and pass after. The limitations: it hasn't been checked against a real warehouse catalog from here. Findings 1 and 2 (the Script as header said the page only reads, and the tree wasn't a keyboard tree) are fixed in #835 (quality PASS 9.1 at ac8faec5), which also takes ALTER and DROP off Fabric's own schemas (finding 3).

## Findings

| # | Severity (blocking / should fix / note) | Finding | Where | Status |
| ---: | --- | --- | --- | --- |
| 1 | should fix | The Script as header and docs say the page runs only queries that read; since WH-10 it runs changes after a confirm. Reword to "Opened, not run" and drop the reason. | app/ui/warehouse.js:48-50; docs/warehouse.md:90 | Fixed: #835 |
| 2 | should fix | The tree isn't a keyboard tree: no `role="tree"`/`treeitem`, no arrow keys, two or three Tab stops per object, and the column toggle has no `aria-expanded`. Usable by Tab, but slow on a large warehouse. Add tree semantics with roving focus, or at least `aria-expanded` on the column toggle, and a keyboard test. | app/ui/warehouse.js:183-230 | Fixed: #835 |
| 3 | note | The explorer uses the same `is_ms_shipped = 0` filter that let Import pick up Fabric's own `queryinsights` and `_rsc` schemas on the tenant run (#809 fixed Import, not the explorer). So the explorer probably lists them too, and offers Script as DROP on them. Listing them may be wanted (query insights); DROP on them isn't. Not checked on a tenant here. | warehouse.js:10-14; compare app/ui/whproject.js:47-50 | Partly fixed: #835 gives objects in `queryinsights`, `_rsc` and `sys` no ALTER or DROP. They are still listed (wanted for query insights); check on the next tenant run |
| 4 | note | The columns query reads every column of every table and view in one run, and `whCatalogQuery` pulls every page into memory. Fine for typical warehouses; on a very large one it's a bigger catalog read. Raised in the #637 review too (quality/pr-review.md:360). | warehouse.js:16-23, :106-128 | Open: low |
| 5 | note | A table's Script as CREATE has column names, types and NULL/NOT NULL only, not constraints (Fabric's NOT ENFORCED primary, unique and foreign keys). Documented. | warehouse.js:55-58; docs/warehouse.md:90 | Documented |
