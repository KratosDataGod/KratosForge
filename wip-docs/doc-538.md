# Mutation testing, batch 538

A re-score of `sql_exec.py`, the SQL page's runs: starting a lakehouse, warehouse or local project run and refusing what it may not do, the run's process and what it reports, its snapshot, pages and exports, and the clean-up of old results. Batch 263 scored it for the first time, at **76.0%** before and **94.7%** after (kinds all), with 8 equivalent mutants. Since batch 263, `main` changed the module three times: #3191 keeps the SQL temp folder out of OneDrive (a folder set there is not used), #3240 times a run's limit on awake time only, waits for each run's reader when the app closes and names a too-long export path, and #3242 lets a DuckDB query parameter come first in the select list.

The run was at `main` be5ef815c (2026-11-28), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6. The per-mutant timeout was raised from 120 to 600 seconds by a wrapper that sets `mutate.TIMEOUT`, with the tool unchanged; no mutant's run timed out. Each pytest session got a fresh temporary folder. Each test set was run with `-x`. The module now has 946 mutants, so 150 were sampled (147 point and 3 boundary). The test set was batch 263's: test_sql_exec, test_sql_exec_cov3, test_sql_exec_edges, test_sql_exec_more_edges, test_sql_params, test_sql_statements, test_sql_page_hardening, test_export_exact, test_local_sql_stop and test_sql_exec_mutation. `test_sql_exec.py::test_service_calls_are_wired_and_audited_as_intended` reads `app/src-tauri/src/watchdog.rs`, so it was deselected, as in batch 263. The set first passed once on the unmutated copy. The "after" run re-ran the 24 survivors with the new file added.

The new tests use a `SqlExecutions` with no worker, a clock that only moves when the test moves it, and a stand-in process whose stdin is a text buffer. The link test makes a symbolic link and skips where that isn't allowed. Before the "after" run, they passed in a copy of `sidecar/` on its own and against the module as `ast.unparse` writes it. They also pass on DuckDB 2.0.0.

### What the survivors were, and the tests that now kill them

- **sql_exec.py**:
  - A SQL temp folder set outside OneDrive is used, and one set inside OneDrive is not (line 326, `and` to `or`).
  - A run's seconds are from its start to its end on the monotonic clock, not from when the run was made (line 224, `is not None` to `is None`).
  - A warehouse change's statements lose the BEGIN TRAN and COMMIT that wrap them, so a dry run judges one statement (line 383).
  - A warehouse change with a malformed precondition is never sent, and says why (line 432, the `raise` removed).
  - A warehouse run is given the warehouse token when its worker asks, and a lakehouse run is told the question is unknown (line 676).
  - A sorted page that reaches the last row has no next page (line 934, `+` to `-`).
  - An earlier session's run folder that is a link keeps the spill it points at (line 1156, and `_linked`'s result dropped at line 1173).
  - An earlier session's result just past an hour's retention is removed (line 1158, 3600 to 3601).
  - A spill folder that is missing or is a file is not taken as quiet (line 1175, `return False` dropped or made `True`).
  - A local run whose temp files reach the project's limit names that limit (line 1301, the `return` dropped). test_disk_full already checks this, but it isn't in the set.
