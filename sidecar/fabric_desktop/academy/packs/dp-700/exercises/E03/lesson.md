# Domains for a data mesh: assign workspaces, delegate settings

Contoso is organizing its Fabric data into business domains. A first draft has the wrong owner on Sales, an admin on a subdomain, the EMEA workspace in the parent domain, and anyone allowed to add workspaces.

## What you'll do

Set up domains and a subdomain for a data mesh: who creates them, who owns them, which workspaces go where and who may assign workspaces.

## How it runs here

This lab is a model, not Fabric. settings.json holds what each team needs and the settings you choose. Check my work reads it as data; Run lists every setting so you can see what the checks read.

## What this run proves

- Your domains, subdomain, admins, contributors and workspace assignments follow the domain roles and rules the domains page describes, checked against a model on this PC.

## What it doesn't prove

- That any domain is created in Fabric: nothing is set here.
- Which tenant settings a domain admin can override for their domain, and default domains.
- Domain images, descriptions and the OneLake catalog's domain view.
