# Mutation testing, batch 531

A re-score of `spark_complex.py` on today's `main`. It types a Spark SQL statement once its tables are bound, and then gives the map forms of `size`, `explode` and `LATERAL VIEW`, Spark's `reverse` and `sequence` of arrays and integers, `typeof`, `to_json`, and an int type for a shift of an int. Batch 86 left it at **92.5%**, and batch 238 at **93.3%** (kinds all), with 10 equivalent mutants. Since batch 238, #3220 made a shift of a shift of an int an int at every step: a new `_arg_type` reads an argument's type from the INT cast a fix already put around it, and `_int_shift_type` reads a shift's argument through it. That fixed the gap batch 238 pinned, and its strict xfail was dropped.

The run was at `main` be5ef815c (2026-11-28), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6. The per-mutant timeout was raised from 120 to 600 seconds by a wrapper that sets `mutate.TIMEOUT`, with the tool unchanged; no mutant's run timed out. Each pytest session got a fresh temporary folder. The module now has 162 mutants, so 150 were sampled. The test set was batch 238's after set: test_spark_complex, test_spark_higher_order, test_spark_complex_mutation, test_spark_complex_cov3, test_spark_complex_rescore and test_spark_builtins_sql_boundary. Test files were given as paths relative to `sidecar/`, and they first passed once on the unmutated copy. `test_spark_complex.py::test_docs_list_what_still_differs` reads `docs/`, so it was deselected, as in batch 238.

### What the survivors were, and the tests that now kill them

No new tests needed. Each survivor is equivalent (see the table below).

The three new ones are in `_arg_type`'s first branch, which returns the type of the INT cast a shift's fix put around an argument. The branch would be needed only when an inner shift is fixed before the shift around it. The marks are taken from a breadth-first walk, so the outer shift (or a `typeof` around it) always comes first, and reads the inner shift through `_int_shift_type` while the inner one is still marked. The INT cast of line 240 is the only `TYPED` cast; `sql.py`'s text casts and `spark_time_zone`'s wrappers mark a bracket or a list read, not a cast. A probe ran ten statements with the branch removed, with shifts of shifts up to three deep, in `typeof`, `to_json`, `sequence`, `array`, `map`, a cast and a subquery, and each gave the same values and types as before.
