# Mutation testing, batch 526

A re-score of `spark_hash.py`, which gives Spark's `hash` (Murmur3) and `xxhash64` as DuckDB SQL, and `sha2` at the bit lengths DuckDB has no function for. Batch 30 scored it at **76.7%** (point mutants), batch 169 its two boundary mutants at **0.0%** (both equivalent), and batch 232 at **72.7%** (kinds all). Since batch 232, `main` changed the module once: #3372 runs `sha2` over a chunk of rows per Python call (`_sha2_chunk`), and `register` also adds `__kf_url_decode`.

The run was at `main` be5ef815c (2026-11-28), with `sidecar/tools/mutate.py` and the method of earlier batches (sample cap 150, seed 7, `--kinds all`), on DuckDB 1.5.6. The per-mutant timeout was raised from 120 to 600 seconds by a wrapper that sets `mutate.TIMEOUT`, with the tool unchanged; no mutant's run timed out. Each pytest session got a fresh temporary folder. Each test set was run with `-x`. The module now has 249 mutants, so 150 were sampled. The test set was batch 232's: test_spark_hash, test_spark_hash_refused, test_spark_hash_mutation, test_spark_hash_rescore and test_spark_hashing_values. Two tests of test_spark_hashing_values read `docs/`, so they were deselected: `test_spark_hashing_functions_answer_as_spark_3_5_or_are_refused_by_name`, as in batch 232, and the newer `test_each_refusal_of_hashing_is_still_needed_and_listed`. The set first passed once on the unmutated copy.
