# Pipeline, notebook or something else: choose the tool for five jobs

Tidewater Freight's data team has five jobs to build. Two engineers want to write everything as notebooks; the operations team wants everything as pipelines. Each job needs the tool that fits who builds it, how much code it takes and how the data arrives.

## What you'll do

Record the right tool for each of five jobs, from a no-code nightly load that runs a notebook to a Kafka feed, and list the activities the pipeline needs.

## How it runs here

This lab is a model, not Fabric. decisions.json holds each scenario and the decision you record for it. Check my work reads it as data; Run lists every value so you can see what the checks read.

## What this run proves

- Your tool for each job matches the persona, code, source and transformation columns and the scenarios of the pipeline, dataflow and Spark decision guide, and the nightly pipeline has the Copy data, Fabric notebook and Teams activities, checked against a model on this PC.

## What it doesn't prove

- That anything runs: no pipeline, notebook, dataflow, copy job or eventstream is built here.
- Whether a job that this exercise gives to one tool could also be built with another one; the checks follow the decision guide's best fit.
- The settings of each activity, such as the notebook's parameters or the Teams message.
