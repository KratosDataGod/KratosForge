## Outcome

**Recommended: Accepted with Documented Limitations.** The product owner decides.

The criterion assumed the semantic model rules would run in Fabric and use capacity. #753 does it differently. It registers SM001 to SM007, the BPA rules that need only a model's definition, as a local `model` checker. They check the model **Update model** would write for the project's last layer, worked out on this PC from the metadata project. So nothing is read from Fabric, no job runs and no capacity is used.

A policy can name the rules, and Check now runs them. Check now never says they run in Fabric, because they don't.

What #753 doesn't cover:
- The rules that need VertiPaq statistics, such as sizes and cardinality. Those need the deployed model in Fabric, and that is #560, still a draft.
- A model that wasn't built by Update model, or one changed in Fabric after deployment.

The limitations table below lists both.

If the product owner accepts:
- the criterion should be reworded as "Check now says where each rule runs and whether it uses capacity";
- the Fabric half needs its own backlog item. PB-112 can't stay open for it once accepted.
